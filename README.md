## Cómo referenciar los proyectos en textos

Puedes referenciar cada proyecto de dos formas:

### Opción 1: Enlazar al repositorio original

Usa la URL del repositorio original del proyecto:

```
https://github.com/odoo/odoo
https://github.com/civicrm/civicrm-core
https://github.com/krayin/laravel-crm
```

### Opción 2: Enlazar a tu fork en GitHub (recomendado para este benchmark)

Si haces un fork de cada repositorio a tu cuenta de GitHub (por ejemplo `ejgbravo`), puedes referenciarlos así:

```
https://github.com/ejgbravo/odoo
https://github.com/ejgbravo/civicrm-core
https://github.com/ejgbravo/laravel-crm
```

**Sí, se puede.** Para hacerlo:

1. Ve al repositorio original en GitHub (p.ej. `https://github.com/odoo/odoo`)
2. Haz clic en el botón **Fork** (arriba a la derecha)
3. Selecciona tu cuenta (`ejgbravo`) como destino del fork
4. Una vez creado el fork, actualiza la URL del submódulo en `.gitmodules` apuntando a tu fork:

```ini
[submodule "proyectos/odoo"]
    path = proyectos/odoo
    url = https://github.com/ejgbravo/odoo
```

5. Ejecuta `git submodule sync` para aplicar los cambios.

De esta forma, en tus textos o artículos puedes escribir:
> "El proyecto Odoo ([ejgbravo/odoo](https://github.com/ejgbravo/odoo)) implementa..."

y el lector verá directamente tu fork con cualquier análisis o anotación que hayas añadido.

## Uso del benchmark

Clona el repositorio con todos los submódulos:

```bash
git clone --recurse-submodules https://github.com/ejgbravo/clean-architecture-benchmark
```

O, si ya tienes el repositorio clonado:

```bash
git submodule update --init --recursive
```
